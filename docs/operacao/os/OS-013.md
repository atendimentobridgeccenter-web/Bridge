## 5. Relatório de entrega (operador)

**OP-01 · 2026-11-11**

### Arquivos alterados

- **`src/pages/admin/LeadProfilePage.tsx`**:
  - Import de `scoreAssessment` (`@/lib/assessment`, função pura já criada na OS-012).
  - `buildAssessmentDisplays(nodes, answers)` — para cada nó `assessment` em `product_nodes`, junta as respostas `{nodeId}.q.*` presentes em `answers`; se nenhuma existir, **pula o nó** (lead não fez esta avaliação → nada muda na tela, critério de aceite). Quando existem, recalcula nível e pontuação com `scoreAssessment` (nunca lê `{nodeId}` nem `{nodeId}.score` gravados pelo navegador — só `{nodeId}.q.*`, como pedido pelo Gate 1). Monta uma linha por questão respondida; se a questão não existe mais na config atual, linha vira `"Questão removida"`; se só a alternativa não existe mais, `"Alternativa removida"` — em ambos os casos `points: null` e não entra na soma (já garantido pelo próprio `scoreAssessment`, que só soma perguntas presentes na config).
  - `isAssessmentTechnicalKey(key, nodes)` — true para `{nodeId}`, `{nodeId}.score` e qualquer `{nodeId}.q.*` de nó `assessment`. Aplicado no filtro de `entries` (lista genérica de respostas), então essas chaves nunca aparecem cruas, tenha o lead feito a avaliação ou não.
  - Novo componente `AssessmentBlock` — card com nível + "X de Y pontos" sempre visível (independente do toggle "N respostas" da entrada, já que é um resumo, não uma resposta crua) e, recolhido por padrão, a lista de questão → alternativa escolhida (+ pontos). Usa só classes de token já presentes no arquivo (`text-ink`, `text-ink-mute`, `text-ink-faint`, `BG_CARD2`, `BORDER2`) — nenhuma cor nova introduzida. Textos em pt-BR.
  - Em `InteractionCard`: `assessmentDisplays` calculado por interação (um bloco por nó `assessment` com dados) e renderizado entre o cabeçalho e o accordion de respostas cruas.

### Decisões de design

- **Nível/pontuação sempre recalculados no navegador** a partir de `{nodeId}.q.*`, nunca lidos do valor gravado — cumpre o cuidado do Gate 1 de bater com a ficha do aluno (que o servidor recalcula do mesmo jeito na OS-010). Não há "mostrar os dois se divergir": só o recalculado é mostrado, que é o único valor confiável para exibição.
- **Bloco por interação, usando o `product_nodes` daquela interação** (não um único cálculo global) — cada `LeadInteraction` já carrega seu próprio `product_nodes` via `useLeadProfile`, então cada card resolve a config do produto daquele momento, correto mesmo que o produto tenha sido reconfigurado entre duas interações do mesmo lead.
- **Bloco de nivelamento sempre visível, perguntas recolhidas por padrão** — meio-termo que atende literalmente "nível, pontuação... e, recolhido, cada questão..." sem reaproveitar o toggle "N respostas" (que é sobre as respostas cruas, conceito diferente).
