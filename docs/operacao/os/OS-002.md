## 1. Contexto (cérebro)
A Edge Function `supabase/functions/sync-stripe-product/index.ts` não verifica quem chama. Ela usa a service_role, cria produto, preço e cupom no Stripe com valores vindos da requisição e sobrescreve `products.price_id_stripe`, que o `create-checkout-session` aceita como válido. Com a anon key pública e o ID de um produto publicado, qualquer pessoa faz um curso custar R$ 0,01.

## 2. Escopo (cérebro)
**Faz:**
- Exigir JWT de usuário com `app_metadata.role = 'admin'`, seguindo o padrão de `provision-teacher-access/index.ts` (401 sem sessão, 403 sem papel admin), antes de qualquer leitura ou chamada ao Stripe.
- Mensagens de erro em pt-BR.
- Garantir que a chamada existente em `src/pages/admin/ProductConfigPage.tsx` continua funcionando (o `supabase.functions.invoke` já envia o JWT da sessão).

**Não faz:**
- Não muda a lógica de criação de produto e preço.
- Não mexe nos outros endpoints (`list-stripe-prices` e webhooks ficam para outra OS).

## 3. Critérios de aceite (cérebro)
- [ ] Requisição sem `Authorization` ou com a anon key → 401, sem tocar no Stripe nem no banco.
- [ ] Usuário logado sem papel admin → 403, sem tocar no Stripe nem no banco.
- [ ] Admin logado → comportamento igual ao de hoje.
- [ ] Preflight `OPTIONS` continua funcionando.
- [ ] typecheck, lint (0 erros) e build limpos.

**2. Testes com curl** (substitua os placeholders; não cole chaves em lugar nenhum além do seu terminal)
```bash
URL="https://<PROJECT_REF>.supabase.co/functions/v1/sync-stripe-product"

# Preflight → 200 "ok"
curl -i -X OPTIONS "$URL"

# Sem Authorization → 401 "Autenticação obrigatória."
curl -i -X POST "$URL" -H "apikey: <ANON_KEY>" -H "Content-Type: application/json" -d '{}'

# Anon key como Bearer → 401 "Sessão inválida."
curl -i -X POST "$URL" -H "apikey: <ANON_KEY>" -H "Authorization: Bearer <ANON_KEY>" \
  -H "Content-Type: application/json" -d '{}'

# Usuário logado sem papel admin (aluno/professor) → 403

  -H "Content-Type: application/json" -d '{}'
```
Observação: se o gateway estiver com `verify_jwt` ligado, o teste "sem Authorization" pode ser barrado pelo próprio gateway com 401 em inglês antes de chegar à função — também é o resultado esperado.
