### Decisões
- **Por que não usar `.br-nav`/`.br-cabecalho` etc. literalmente nos layouts:**
  essas classes do `bundle.css` são seletores de topo independentes (não exigem
  `.br` ancestral — só as 3 regras de base citadas acima exigem), mas `.br-nav`
  define `width: 248px` fixo, incompatível com o menu recolhido. A solução foi
  escrever o trilho com os mesmos tokens de cor/tipografia do componente, mas em
  Tailwind/inline, preservando a largura variável.
- Hover/foco: todo `onMouseEnter`/`onMouseLeave` que mutava `style` diretamente
  nos 5 arquivos-alvo foi substituído por classes `hover:`/`focus-visible:` do
  Tailwind ligadas aos tokens (`var(--foco)` para o anel de foco em todo controle
  interativo tocado — botões, links, campos).
- Tailwind já expõe os tokens novos como cores nomeadas (`bg-superficie`,
  `text-texto-mute`, `border-line`, `bg-laranja-suave`, `rounded-grande` etc.,
  configurados em `tailwind.config.ts` desde a OS-015) — por isso a maior parte do
  código usa essas classes em vez de `style={{ background: TOKEN }}` espalhado.
