## 1. Contexto (cérebro)
O app tem só 2 componentes compartilhados (`DeleteButton`, `ThemeToggle`); cada tela monta os seus botões, tabelas e etiquetas, e é daí que vem a inconsistência. Esta OS cria os componentes React do design system, para as telas usarem nas OS seguintes.

Referência obrigatória: `docs/design-system/README.md` (regras), `docs/design-system/tokens.json` e `tokens.css` (valores), `docs/design-system/components/*/` (cada componente com README e `preview.html` de referência visual) e as telas de exemplo `components/TelaHoje` e `components/TelaAluno`. Design aprovado pelo Everton em 10/11/2026. Versão navegável: https://claude.ai/artifact/TbgRFtHiuJM7aPANFgcrue

## 2. Escopo (cérebro)
**Faz:**
- Em `src/components/ui/`, um componente por arquivo, com tipos exportados, fiel ao README e ao `preview.html` de cada um:
  `Botao` (primario, secundario, fantasma, perigo, icone; carregando; desabilitado), `Campo` (rótulo, ajuda, erro, prefixo; input/select/textarea), `Etiqueta` (ok, atencao, erro, info, marca, neutra), `Nivel` (confirmado, previsto), `Cartao`, `TituloSecao` (com kanji e ação), `Tabela` (wrap, cabeçalho, linha, célula numérica, rodapé) + `Pessoa`/`Avatar`, `Arco`, `Jornada`, `Resumo`, `Cabecalho`, `Vazio`.
- Estilos por token (Tailwind ou CSS do `docs/design-system/components/bundle.css` portado para `src/styles/`), sem hexadecimal.
- Acessibilidade de cada README: `aria-label` em botão-ícone, `aria-invalid` + mensagem no erro de campo, `role="img"` + `aria-label` no Arco, `aria-busy` no carregando.
- Ícones: continuar com `lucide-react` (traço 1,75), 18px em botões e 14px em etiquetas.
- Uma página interna só para desenvolvimento, `/admin/_design` (fora do menu), mostrando todos os componentes nos dois temas.

**Não faz:**
- Não troca nenhuma tela existente para os componentes novos.
- Não remove `DeleteButton` nem `ThemeToggle` (podem ser reescritos por dentro com `Botao`).

### Decisões de implementação (não cobertas em detalhe pela Escopo/Gate 1)
- **Campo**: em vez de pedir que o consumidor replique `aria-invalid`/`aria-describedby` manualmente no controle, o componente clona o filho (`cloneElement`) e injeta `id`, `aria-invalid` e `aria-describedby` sozinho — reduz a chance de alguém esquecer, sem mudar a API pedida ("o consumidor fornece... o controle").
- **Nivel**: reaproveitei o tipo `JlptLevel` já exportado de `src/components/form-builder/FormBuilder.tsx` (OS-011), via `import type` (sem custo de bundle — é só tipo, apagado na compilação).
- **Etiqueta**: ícone por `ComponentType<SVGProps<SVGSVGElement>>`, para aceitar qualquer ícone `lucide-react` diretamente (ex.: `<Etiqueta variante="ok" icone={CheckCircle2}>`); README não exige ícone em `marca`/`neutra`, então ficou opcional.
- **Jornada**: achado e documentado em comentário no próprio arquivo — o README permite até 5 etapas, mas `bundle.css` fixa `grid-template-columns: repeat(4, 1fr)`; portei o CSS fiel ao bundle (não é desta OS redesenhar) e deixei a nota para quem usar com 5 etapas.
- **`/admin/_design`**: a página não tenta mostrar os dois temas simultaneamente lado a lado — o app inteiro vira com um único `data-theme` no `<html>` (`src/lib/useTheme.ts`), então não há como um tema "escuro" local coexistir com o tema real da página sem reimplementar o mecanismo de tokens. Para conferir nos dois temas, uso o seletor de tema normal da topbar (já renderizado pelo `AdminLayout`).
